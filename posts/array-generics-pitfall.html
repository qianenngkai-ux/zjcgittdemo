Array<T> 与 Array<U> 的类型陷阱

2026-09-02 · TypeScript JavaScript · 6 分钟

泛型的协变与逆变是 TypeScript 里最容易被跳过的一节。跳过它的代价是：某天你会写出一段编译通过、运行时报错的代码。

数组是协变的，这是个问题

TypeScript 默认认为数组是协变的：如果 Dog 是 Animal 的子类型，那么 Array<Dog> 也可以赋给 Array<Animal>。

interface Animal { name: string }
interface Dog extends Animal { bark(): void }

const dogs: Dog[] = [{ name: 'Rex', bark() {} }];
const animals: Animal[] = dogs;  // 编译通过

animals.push({ name: 'Cat' });   // 编译通过
dogs[1].bark();                  // 运行时崩溃：bark is not a function

问题出在最后一行——dogs 里混进了一个没有 bark 的对象。类型系统本该拦住这件事。

为什么 TypeScript 允许

这是为实用性做的妥协。数组的可读用法（遍历、map）远多于可写用法，如果严格用不变（invariant）处理，大量正常代码会报错。官方在文档里称这是「刻意的不健全」。

怎么规避

需要可写时，用 readonly 明确表达意图：

function sum(values: readonly number[]): number {
  return values.reduce((a, b) => a + b, 0);
}

readonly T[] 不允许 push，因此协变是安全的。函数参数位置上的数组，默认写成 readonly 能避免这类问题。

小结

看到 Array<T> 出现在会被修改的位置时，多问一句「这里真的需要往里写吗」。不需要的话就加 readonly。
