# 个人技术博客 — 设计文档

日期：2026-09-16
状态：已确认，待实现

## 目标

一个个人技术博客，内容以中文技术文章为主。技术栈限定为原生 HTML5 + CSS + JavaScript，不使用任何框架、构建工具或包管理器。

成功标准：

- 双击任意 HTML 文件即可在浏览器预览，无需启动本地服务器
- 新增一篇文章只需两步：复制模板写内容、在数据文件里加一条记录
- 零 npm 依赖、零构建步骤、零外部 CDN 请求

## 非目标

以下功能明确不做，避免范围蔓延：

- 站内搜索
- 文章目录（TOC）
- 评论系统
- RSS / Atom 订阅
- 分页
- 语法高亮（见「代码块」一节）

## 架构决策

### 决策 1：每篇文章是独立的 HTML 文件

文章的正文内容直接写在 `posts/<slug>.html` 里，首页列表由数据文件驱动。

**为什么**：正文可以是任意复杂的 HTML——代码块、图片、表格、内嵌 demo——不受数据格式限制。每篇文章是独立页面，加载快，且双击即可打开。代价是新增文章要复制一次模板，对个人博客的发布频率而言可以接受。

**被否决的方案**：

- 正文存进 JS 数组：正文得写成字符串，排版复杂的内容难写难维护。
- Markdown + 运行时解析：写作体验最好，但浏览器在 `file://` 下无法 `fetch` 本地 `.md` 文件（CORS 限制），必须起本地服务器才能预览，破坏了「双击即可预览」的目标。

### 决策 2：用全局变量，不用 ES Module

`assets/js/*.js` 之间通过全局变量通信，而不是 `import` / `export`。

**为什么**：`<script type="module">` 在 `file://` 协议下会被浏览器按 CORS 规则拦截，页面直接报错白屏。改用普通 `<script src>` 加全局变量后，双击 HTML 即可正常工作，这是本项目「无服务器预览」目标的必要条件。

**约束**：因此 `posts.js` 声明的 `POSTS` 必须是全局的（顶层 `const`，不加 IIFE 包裹），且 `posts.js` 的 `<script>` 标签必须排在 `home.js` 之前。

### 决策 3：代码块做样式，不做语法高亮

代码块具备深色底、等宽字体、横向滚动、语言标签，但不对关键字着色。

**为什么**：语法高亮要么引入 highlight.js（增加一个外部 CDN 依赖和运行时开销），要么手写数百行正则。两者都与「零依赖、简单」的目标冲突。样式化的代码块已经能保证可读性。

**后续**：若之后需要高亮，可在不改动现有结构的前提下单独加入。

## 数据模型

`assets/js/posts.js` 定义唯一的数据源：

```js
const POSTS = [
  {
    slug: 'understanding-closures',   // 对应 posts/<slug>.html，需唯一
    title: '理解闭包到底在讲什么',
    date: '2026-09-16',               // ISO 格式，用于排序与显示
    tags: ['JavaScript'],             // 字符串数组，可多个
    summary: '从作用域链说起，聊聊闭包到底解决了什么问题。',
    readingTime: 5                    // 分钟，人工估算填写
  }
];
```

字段约束：

- `slug` 必须与 `posts/` 下的文件名（去掉 `.html`）一致，否则链接 404
- `date` 使用 `YYYY-MM-DD`，列表按此字段倒序排列
- `tags` 至少一个；标签全集由程序从所有文章中自动去重提取，无需单独维护
- `readingTime` 由作者估算，不自动计算

## 页面设计

### 共用导航

三个页面（首页、文章页、关于页）顶部共用同一套导航：站点标题（点击回首页）、关于链接、主题切换按钮。文章页额外有「← 返回首页」链接。导航结构在每个 HTML 文件中各写一份（无构建步骤下无法共享片段），但样式与行为完全由 `main.css` 和 `theme.js` 统一控制。

### 首页 `index.html`
- 标签栏：由 `POSTS` 中所有文章的标签去重生成，点击筛选，再次点击取消
- 文章列表：每条显示「日期 · 标签 · 标题 / 摘要 · 阅读时长」，整条可点击进入文章页
- 列表按 `date` 倒序

### 文章页 `posts/*.html`

- 返回首页链接
- 标题、日期、标签
- 正文（使用 `post.css` 的排版样式）
- 底部：上一篇 / 下一篇导航

### 关于页 `about.html`

- 结构复用文章页的排版样式
- 自我介绍 + 联系方式

## 主题切换

`theme.js` 的 `<script>` 标签必须放在 `<head>` 中，且**不能加 `defer` 或 `async`**，也不能移到 `<body>` 末尾。

**为什么**：脚本若延迟执行，浏览器会先用默认（浅色）渲染一帧再切到深色，产生白屏闪烁（FOUC）。放在 `<head>` 且不加 `defer`/`async` 的普通 `<script src>` 会阻塞解析、同步执行，保证首帧渲染前 `data-theme` 已经写在 `<html>` 上。

解析顺序：

1. 读取 `localStorage` 中的用户选择
2. 若无，读取系统偏好 `prefers-color-scheme`
3. 将结果写入 `<html data-theme="light|dark">`

CSS 中定义两套颜色变量，切换主题只改变量值，不改变任何布局规则。用户的显式选择一旦产生，就持续覆盖系统偏好。

## 标签筛选

- 标签全集从 `POSTS` 所有文章的 `tags` 中自动去重提取
- 点击标签筛选列表，再次点击同一标签取消筛选
- 筛选状态同步到 URL hash（`index.html#tag=JavaScript`），使筛选结果可直接分享；页面加载时读取 hash 恢复筛选状态

## 实现顺序

1. 项目骨架 + `posts.js` 数据文件

5. `post.css` 正文排版
6. 文章模板 + 两篇示例文章
7. 关于页
8. README 发布流程说明
